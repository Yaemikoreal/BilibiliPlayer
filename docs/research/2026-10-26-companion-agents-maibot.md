## 1. MaiBot 的定位与架构

### 1.1 它是什么（定位，决定了它为什么这么做）

README 原文（【①原文】）：

> 麦麦 MaiSaka 是一个基于大语言模型的可交互智能体。……她还是一个**致力于了解你，并以真实人类的风格进行交互的数字生命**。她不追求完美，不追求高效，但追求亲切和真实。

作者千石可乐的设计原则（README 引述，【①原文】）：

> - 核心的原则：**"最像而不是好"**。
> - 若人类真的需要 AI 陪伴……并不是所有人都需要一个完美的、能解决所有问题的 "helpful assistant"，而是一个**会犯错、拥有自己感知和想法**的"生命形式"。

对照我们的处境：**这句话的方向和我们一致，但落点不同**。麦麦的"会犯错"体现在错别字、分段刷屏、不接话——这些在**私域群聊**里是可爱；在我们的**公开评论区**里是事故（不可撤回，见 §6.2）。所以"最像而不是好"这句话**不能整句照搬**，要改成：**"最像，但错要犯在不会被截图的地方"**。

### 1.2 模块划分（架构，【①原文】按文档目录归纳）

文档站的配置目录基本就是它的功能地图：

| 层 | 模块（文档原名） | 干什么 |
|---|---|---|
| **决策层** | Planner（规划器）+ `[chat.reply_timing]` | 决定**要不要开口**、等多久、被打断怎么办 |
| | `[chat.reply_style]` / `[personality]` | 决定**以什么身份/口吻**开口 |
| **表达层** | Replyer（回复器）+ `[response_post_process]` | 把结论写成"人话"（错字、分段、打字速度） |
| **学习层** | `[expression]` 表达学习 / `[jargon]` 黑话学习 | 从群里**学说话方式与梗**，带范围控制与审核闸门 |
| **记忆层** | **A_Memorix**（独立长记忆子系统，12 个子段落） | 段落/实体/关系向量、图片记忆、按"聊天流"隔离 |
| **感知层** | `[visual]` 视觉 / `[voice]` 语音 / `[emoji]` 表情包 | 看图、听语音、**偷别人的表情** |
| **上下文层** | `[chat].max_context_size=40`、滚动状态摘要 `context_compaction_summary_max_chars=6000` | 长对话压缩 |
| **外设** | 适配器 / 插件运行时 / MCP / `[agent]` ACP（可接 dsh） | 平台接入与扩展 |

**消息流水线**（【②共识】，由"新消息先经过防抖合并，再由 Planner 决定是否回应"+ Replyer 提示词 + 回复后处理三处文档交叉印证）：

```
消息 → 防抖合并成"一批" → Planner（思考：wait / 调工具 / 决定说或不说）
     → Replyer（写正文）→ 后处理（错字 → 分段 → 打字速度）
     → 发送（可带引用 / 表情包）
```

⭐ **对我们最有用的结构性观察**：MaiBot 把"**要不要说**"和"**怎么说**"拆成**两个不同模型角色、两段不同提示词**。我们目前是**一个 prompt 一次生成**，于是"决定说"和"写这句"在同一段推理里互相污染——这大概率是我们"5 条同型"的结构性原因之一（【③推断】，见 §5-N1）。

### 2.1 说话决策：它怎么决定"这条要不要说"

这是 MaiBot 最值得学的部分，因为它**不是**用一句"请判断是否回复"的提示词，而是**三层混合**（【①原文】+【③推断】分层）：

**(a) 硬阈值层 —— 频率**：`talk_value` 是一个 0~1 的"发言倾向"旋钮，不是判决。「麦麦话太多或话太少怎么办」官方答案是：先调频率，再检查时段规则，**最后**才是"人格和群聊提示词也会影响 Planner 对'是否应该说话'的判断"。⭐ 注意这个**优先级顺序**：**先数值、后提示词**。我们现在的做法正好相反——靠提示词里写"只在有真话可说时发"，这等于把**配额纪律交给模型自由裁量**（这是"凑数发"和"5 条同型"的温床，【③推断】）。

**(b) 时间层 —— 作息**：`talk_value_rules` 支持 `{platform, item_id, rule_type, time, value}`，`time` 支持**跨天区间** `"23:00-02:59"`，未命中时走"全局兜底"。文档给出的默认规则是 **`00:00-08:59 → 0.8`（更安静）**、`09:00-18:59 → 1.0`。**"凌晨说话频率自动降低"是写进默认配置的**，不是靠模型自觉——这是**作息感的正确实现方式：把它算出来，别让模型猜**。

**(c) 反馈层 —— 不说话的代价**：连续决定"不回"之后，`no_action_backoff_*` 让**下一次检查前先等一会儿**（起 15 秒、上限 300 秒、连续 2 次开始放慢），除非等待期间新消息累积到 `bypass_pending_count=6` 条。⭐ 这个机制的真正价值不是省算力，而是给"沉默"一个**自然后果**：人不会每 3 秒重新评估一次"我该不该插话"，聊到一定热度才回头。**这正好治我们"同一轮里反复权衡该不该评"的病**（duty.md 已经用纪律硬压："拿不准就按跳过处理"，MaiBot 给的是机制化版本）。

**(d) 另有一条容易被忽略的**：群聊提示词里直接写人类语气的策略（【①原文】）：

> 控制回复的频率，不要每个人的消息都回复，优先回复你感兴趣的或者主动提及你的，适当回复其他话题。

**"优先回复你感兴趣的"**——把"兴趣"当作回复优先级的显式依据，而不是"有没有价值"。这句话可以直接改写进我们的人设模块（§5-N1）。

### 2.2 群体语感学习：它怎么"学群友怎么说话"

这是 MaiBot 与我们差别最大、也最该借鉴的一块。它的表达学习是**"语料 → 审核 → 入库 → 带权重抽取 → 注入"**的闭环（【①原文】各环节，【③推断】串成闭环）：

1. **采集**：从群聊里学表达方式，`max_expression_learner=3` 控制并发学习任务数。
2. **审核**：`expression_self_reflect=true` —— **写入前先让 AI 审核**，文档原话是"减少学到奇怪内容"；`expression_checked_only=false` 时"未精选的表达也会使用"，设 `true` 则**只用人工审核过的**。
3. **入库与索引**：表达向量索引"自动维护新增数据、历史回填与失败恢复；索引文件损坏时自动重建"。
4. **选取（两档）**：
   - **快速档 `false`（默认）**：**加权随机抽取**表达直接注入，**不额外调用模型**；
   - **精细档 `true`**：用"表达意图"与嵌入召回，**再由 LLM 按语境筛选**，候选池硬上限 50。
5. **作用域**：`learning_list` 每条规则管一个范围（具体聊天 > 平台默认 > 全局默认，**越具体越优先**），`use`/`learn` **分开**控制；`expression_groups` 让多个聊天共享学到的表达。`item_id` **不支持通配 `*`**，只有互通组支持。

**黑话学习 `[jargon]`** 是同一套机制换对象（"群里的黑话梗"）。⭐ 但 FAQ 对"黑话要出现多少次才会学"的回答非常诚实，值得整段抄进我们的设计约束（【①原文】）：

> 样本数量、上下文是否一致、表达是否稳定以及学习模型都会影响结果。出现次数太少时通常无法可靠推测含义；随着一致样本增加，结果才可能逐渐稳定。……**不建议在文档中承诺固定次数或百分之百准确。**

**这条对我们是个警告**：我们的"见闻库/梗库"如果按"看过一次就记"来建，会**积累一堆误读的梗**（评论区玩梗一半是反串和阴阳）。官方文档自己都不敢承诺准确率，我们不能假装自己的自动积累是可靠的。

### 2.3 记忆与关系：A_Memorix 到底记什么

【①原文】要点（细节在独立文档页，本次未展开）：

- 独立长记忆子系统，配置文件含 **12 个子段落**，总开关 `[a_memorix.plugin].enabled`。
- 记的东西分**段落 / 实体 / 关系向量**三类；**关系向量默认关闭**（"为什么提示关系向量未启用"是常见 FAQ），由 `a_memorix.retrieval.relation_vectorization` 控制，开启涉及"历史数据回填会产生额外请求"。
- **图片记忆**是独立能力，需要单独的 `[model_task_config.image_embedding]`，**文本 embedding 不能替代**；FAQ 明确"相似图召回"要区分**精确同图（内容哈希）**与**视觉相似（向量接近）**，"不能据此认定两张照片是同一对象"。
- **作用域按"聊天流"隔离**：默认只检索当前聊天流，共享组内互通，未共享的查不到彼此。
- 记忆会记错（"把人物或主客体记反"是 FAQ 条目），修法是**查来源消息 → 换抽取模型 → 纠错/删除重写**。
- **表情包不入库**（有自己的识别与发送逻辑）。

⭐ **对我们的直接含义**：MaiBot 的记忆是**"了解一个人"**（实体+关系），我们的记忆是**"我做过什么"**（判重表/账本）。**两者不是一回事，不能照搬**。但有一个可以搬：**"记忆会记错，所以需要来源与纠错通道"** —— 我们的见闻库将来一定会记错视频内容，需要"来源 BV 号 + 可删除重写"（§5-N9）。

### 2.4 输出层：那些"像人"的小动作（多数我们不能用）

- **错别字**：`error_rate=0.01`（单字被替换概率）、`min_freq=9`（**只对常见字**制造错字，生僻字不动，避免一眼假）、`tone_error_rate=0.1`（按相近声调错）、`word_replace_rate=0.006`（整词替换）、`enable_correction_quote=true`（**纠正错别字时引用上一条**——打完错字再自己补一句，这是极强的真人信号）。
- **分段**：把过长回复拆成多条发，"更像真人刷屏"；`max_split_num=3`。
- **表情包**：`steal_emoji` 自动收集别人的表情，`max_reg_num=64` 满额替换，`emoji_send_num=25`（**从 25 个候选里挑 1 张，不是发 25 张**——这个参数名很容易被误读）。
- **引用**：`often` 的引用概率是 `occasionally` 的两倍；私聊还会结合"用户连发条数、发言间隔、回复目标位置"决定。

⚠️ 这一整段（错字/分段/表情包/引用）在我们的场景里**绝大多数是负资产**，理由见 §6。

### 2.5 人设与状态：把"人格"拆成可调的三件事

【①原文】`[personality]` 三段职责分得很清楚，文档还给了每段"该写多长"的建议：

- `personality` —— "她是谁、什么性格"，**写 1~2 句即可，太长反而稀释效果**；
- `behavior_style` —— **行动准则**：什么时候参与、怎么观察、什么时候安静。文档示例原文：**"不会没话题硬找话题：群里聊到感兴趣的内容再插话，冷场时安静旁观，不刷屏。"**
- `reply_style` —— 说话习惯（简短还是话痨、温和还是毒舌）；
- `multiple_reply_style[]` + `multiple_probability` —— **按概率临时注入一条备用风格**，只影响本次回复，"想玩人格随机切换就把概率调到 0.1~0.3"。

⭐ **`behavior_style` 这一格是我们人设卡里缺的**：我们的人设卡有 identity/voice/mindset/taste/stance/redlines，但**没有"何时开口/何时闭嘴"的独立字段**，这条纪律现在散落在 duty.md 的"评论纪律"里，和"怎么写"混在一起。这是可以直接补的一格（§5-N1）。

⭐ 还有两条排错口径，等于替我们踩过坑（【①原文】）：
- 「**人设改了感觉没变化**」→ "人设只影响新生成的回复，已发出的消息不会变……想让风格偶尔突变，试试 `multiple_reply_style` + `multiple_probability`"。
- 「**麦麦刷屏话痨**」→ "调低 `talk_value`（如 0.3）；`max_sentence_num` 和 `max_split_num` 限制单次回复条数；注意 `emoji_send_num` 只是发送候选数，**调小它不会减少发言频率**"。

## 3. 同类对比：Pallas-Bot（牛牛）与 AstrBot

### 3.1 Pallas-Bot（牛牛）：**"语料优先"的另一条路**（比 MaiBot 更接近我们）

牛牛是 NoneBot 生态的老牌 QQ 群聊机器人，README 里对 V4 的自述是【①原文】：**"我仍想把复读放在前面——模型轻轻托一把就好，群友的话才是她真正的声音"**。它的定位是"**复读机**"（"群友说什么牛牛就说什么"），但把这件事工程化了：

| 牛牛的机制 | README 原文要点 | 为什么对我们特别重要 |
|---|---|---|
| **学习型复读** | "从群聊语料学习，自动接话、跟复读与贴表情；**接话积极度与复读频率可调**" | 把"像不像群里人"变成**两个可调旋钮**，而不是提示词形容词 |
| **语料联邦** | "可选接入**社区共享语料池**，扩充接话短句来源；多部署可共池互认，按群归属与消息抢占去重，**避免重复回复**" | ⭐ **语料是资产、要共享、要去重**——这三件事我们现在都缺 |
| **语义风格指导** | "由复读引擎**按账号与群维度**学习「**什么场合常说什么**」，作为**群表达指导**注入 LLM 对话；**同群不同账号互不干扰**" | ⭐⭐ 这是"形态/场合 → 典型说法"的**显式映射表**，正对我们"5 条同型" |
| **约束关系** | "输出受**账号人格**与**本群表达风格**约束" | 人格（我是谁）+ 场域语感（这里的人怎么说）**两个输入**，不是一个大 prompt |
| **金句投稿墙** | 社区主站有"金句投稿墙"，可投稿牛牛消息正文 | **人工筛选好句子入库**——低成本高质量的表达库来源 |
| **LLM 对话** | 明确 `@` 时才多轮对话；支持群内长期记忆、**人物观察**、知识检索、联网搜索 | 它把"多轮陪聊"当**可选能力**，默认仍是短接话 |

**牛牛的可迁移度高于 MaiBot**：因为它的默认形态就是**短、单发、无上下文依赖的接话**，和我们的"公开短评论"结构上同构（【③推断】）。它证明了一件事：**活人感的主要来源可以是"语料"而不是"记忆"**——只要语料是按"什么场合说什么"组织的。

### 3.2 AstrBot：**"平台/插件型"路线，机制的对照组**

README 只给能力清单（【①原文】）：LLM 对话、多模态、Agent、MCP、Skills、**知识库**、**Persona Settings**、**自动上下文压缩**、15+ 平台适配、1000+ 插件、Agent 沙箱、WebUI/ChatUI。它**没有**在 README 层描述：如何决定要不要说话、如何学习群友说话方式、如何管理黑话与梗。

⚠️ 因此关于 AstrBot 只能下这个结论：**它是"可扩展的对话平台"，活人感靠插件与提示词自行实现**；具体某个"主动回复/概率发言"插件的行为 `[未查证]`（本次未查插件市场与源码，不作断言）。

## 4. 场景差异：群聊 vs B站评论区，逐条判定

**前提差异（我们的硬约束，不可协商）**：公开短评 10–100 字 / **单轮、无对话上下文** / **不可撤回** / **有平台红线** / **无固定对话对象**（回复我的人是例外，且是异步的）。

| # | 群聊里成立的做法 | 我们的场景 | 判定 | 改造后落到哪 |
|---|---|---|---|---|
| 1 | 多轮上下文（`max_context_size=40`） | 单轮，没有上一句 | **不适用**（直接注入历史有害） | —— |
| 2 | 防抖合并"一批消息" | 我们一次只处理一条视频/一条评论 | **不适用** | —— |
| 3 | 分段发送（`response_splitter`） | 单条评论即全部，连发=刷屏 | **🔴 必须拒绝** | §6.1 |
| 4 | 生成错别字并事后纠正 | 不可撤回，错字永久挂账号名下 | **🔴 必须拒绝** | §6.2 |
| 5 | 贴表情包 / 偷表情 | B站评论只有文本 emoji（`[doge]`），且有频率上限 | **改造后用** | 人设卡"标点与表情"节，已有"一条最多一个"+白名单 |

### N1 · 把"要不要说"独立成一格，并前置到生成之前

- **来源**：MaiBot `[personality].behavior_style`（【①原文】"不会没话题硬找话题：群里聊到感兴趣的内容再插话，冷场时安静旁观，不刷屏"）+ FAQ 的**优先级口径**（【①原文】"先调频率 → 再检查时段规则 → **最后**才是人格和提示词影响 Planner 的判断"）。
- **机制**：MaiBot 把"人格"拆成三段：**她是谁** / **何时参与、何时安静** / **说话习惯**。第三段（何时参与）在今天的我们这里**根本不存在**——我们的"评论纪律"把"该不该评"和"怎么写"塞在同一段提示词里，模型于是**边判断边写**，写出来的必然是"我先评价一下"的骨架。
- **落地**：
  1. 人设卡新增字段 **`behaviorStyle`**（建议 3 行）：`什么场景才开口` / `什么场景闭嘴` / `兴趣优先于价值`。
  2. 在 `duty.md`「评论纪律」**最前面**加一条硬前置：**先给出"发/不发"的一个词结论，再写正文**（迫使决策与表达串行，而不是并行）。
  3. 把频率类纪律从提示词挪进**宿主计算的本轮参数**（我们已经这么做了配额，继续扩大：**"本轮该发几条"由宿主算，模型不许自我加码**）。
- **预期解决**：**F2**（同型源于"边判边写"）、**F3**（判断式收尾正是"我要评价"的副产品）。

### N2 · 建"表达库"：按场合分桶的真实语料，替代形容词式风格约束

- **来源**：Pallas-Bot README【①原文】"由复读引擎**按账号与群维度**学习「**什么场合常说什么**」，作为**群表达指导**注入 LLM 对话"；MaiBot `[expression]` 表达学习（【①原文】）+ 两档选择中"**加权随机抽取**表达直接注入"（默认档，不额外调模型）。
- **机制**：⭐ 两家都不靠"请写得口语一点"这类形容词，而是**把"什么场合说什么"变成可检索的真实句子**。我们已经有"形态欠账"，但**欠的是形态名，不是句子**——所以模型知道"该发疑问"，却只会写出书面疑问。
- **落地**：
  1. 新增 `data/expression-bank.json`（人设模块资产，不进 prompt）：按桶存 `纯反应 / 疑问 / 个人经历 / 玩梗 / 补细节 / 吐槽`，每桶 20–40 条，**来源必须是真实热评原文**（我们已有 247 条热评语料，见 `2026-10-25-human-comments-corpus.md`）。
  2. 检索规则：宿主按**形态欠账**决定桶 → **加权随机抽 3–5 条同桶样本**注入"最后一公里 3 行"（对应 MaiBot 候选池硬上限，**别超过 5 条**，多了模型会照抄）。
  3. **只给手感，不给内容**：注入时附一句"这些是别人怎么说，不是让你改写"。我们 persona 里已有"学密度，不学内容，不抄"的纪律，把它**从提醒升级成注入结构**。
- **预期解决**：**F5**（语感不对是最大痛点）、**F2**（同一形态永远同一个腔调）。

### N3 · 入库审核闸门：学到的表达必须先过审，且分"候选/启用/退役"

- **来源**：MaiBot【①原文】`expression_self_reflect=true`（写入前先让 AI 审核，"减少学到奇怪内容"）、`expression_checked_only`（**只用人工精选**）、`learning_list` 的 `use`/`learn` 分离。
- **机制**：自动学习会学到反串、阴阳、广告和错别字梗。MaiBot 的答案是**双闸门**：机器先自审，人再精选；且**学与用分离**（可以"继续学但先不用"）。
- **落地**：
  1. 表达库每条带 `status: candidate | active | retired`；**只有 `active` 能被注入**。
  2. 入库流程：抓热评 → **规则过滤**（长度 5–40、无链接、无 @、无脏词、非广告）→ **AI 自审一条**（判"这句是不是在阴阳/引战/反串"）→ `candidate`；人工（或 lint 抽样）确认后 `active`。
  3. 我们的 **lint 已经是确定性质量门**，再加一条**确定性检查**：正文与库中某条 `active` 的**字符级重合 > 60% ⇒ 拒绝**（防抄袭热评，那是平台红线，也是"水军"特征）。
- **预期解决**：**F5**（防止把阴阳语当"社区味"学进来）、以及 OOC/红线风险。

### N4 · 时段与作息：把"现在几点"算出来写进状态，而不是让模型猜

- **来源**：MaiBot【①原文】`talk_value_rules`：`time="00:00-08:59"` → `value=0.8`（**更安静**）、`09:00-18:59` → `1.0`，支持跨天 `23:00-02:00`；未命中走全局兜底。
- **机制**：**"凌晨话少"是写在默认配置里的数值**，不是"请考虑时间"的提示词。
- **落地**：
  1. 「今日状态」块加一行**机器算好的**：`时段：深夜(02:00) / 早 / 午 / 晚`。
  2. 时段 → **长度与形态偏置**（宿主算，不靠模型）：深夜 = 上限压到 40 字、**禁"经验分享"长形态**、允许"半句/省略号"；白天正常。
  3. 顺带解决一个隐性失真：我们的"今日状态"现在只有 mood + 最近 3 条，**没有时间**，所以任何一轮读起来都像白天有精神。
- **预期解决**：**F4**（每轮温度一样）。

### N5 · 沉默退避：把"今天不太想说话"变成机制，而不是纪律

- **来源**：MaiBot【①原文】`no_action_backoff_base_seconds=15` / `cap_seconds=300` / `start_count=2` / `bypass_pending_count=6`（连续决定不回 → 下次检查**先等一会儿**，直到攒够新消息再回来看）。
- **机制**：给"沉默"一个**自然后果**：不是每次都重新评估，而是"聊热了再回头看"。
- **落地**：
  1. 宿主在**今日状态**里维护 `skipStreak`（连续跳过条数）：`skipStreak ≥ 3` ⇒ 本轮**只允许发 1 条**，且**只能从"纯反应/玩梗"桶里选**（低能量形态）。
  2. 与 `duty.md`「预算与反内耗」合流：**"再看一条"要有代价**——每多看一条候选，本轮可发条数不变但**字数上限 -5**（简单、可解释、省 token）。
  3. ⚠️ 不要照抄"按秒退避"——我们是**按轮**跑的，单位要从秒换成"轮"。
- **预期解决**：**F2**（"凑数发"是同型的直接原因）、以及反内耗省钱。

### N6 · 梗与见闻的生命周期：容量上限 + 满额替换 + TTL + 学用分离

- **来源**：MaiBot【①原文】`[emoji].max_reg_num=64`（最多存 64 个）+ `do_replace=true`（**满额后用新的替换旧的**）+ `check_interval=10`；`learning_list` 的 `use`/`learn` 分离；FAQ【①原文】"黑话要出现多少次才学……**不建议承诺固定次数或百分之百准确**"。
- **机制**：⭐ 这一条是我**最想补进我们见闻库**的：MaiBot **连表情都有容量上限和淘汰策略**。我们的见闻库/`loreIndex` 是**只增不减**的，后果是"越用越旧"——模型总会抽到最早、最常被抽到的那几条，于是**每轮都像同一个人**（正是 F4）。
- **落地**（改的是 schema，不改代码逻辑）：
  1. 每条见闻/梗加四个字段：`status`(candidate/active/retired)、`heat`(被用次数)、`lastUsed`(ISO)、`ttlDays`(默认 90)。
  2. **容量**：`active` 上限（如 120 条），**满了不许再入库**，先按 `heat` 最低 + `lastUsed` 最旧淘汰 —— 对应 `max_reg_num` + `do_replace`。
  3. **抽取**：按 `heat` **反比**加权（刚用过的降权），确保"最近 5 条欠哪种形态"能真的抽到新东西。
  4. **学用分离**：新梗默认 `candidate`，只有被用过且**没人反驳**（有回复/有赞）才升 `active` —— 对应 `use`/`learn`。
- **预期解决**：**F2**（总用同几个梗）、**F4**（越用越旧）。

### N7 · 楼中楼优先：唯一有"上下文"的地方，要当成主战场

- **来源**：MaiBot【①原文】`inevitable_at_reply=true`（被 @ 时尽量回）、`group_quote_frequency`（引用频率可调）；我们的 `duty.md`【①现状】已有「跟进纪律」与「发完 30–60 分钟内回查一次」。
- **机制**：在群聊里，"被点名"是最高优先级的开口理由。我们有同构物：**别人回复我的评论** —— 这是唯一**有真实上下文、有对象、可以自然说"我"**的场景。
- **落地**：
  1. 把「跟进」的优先级**明确排在"铺新评论"之前**（duty.md 已写"优先级高于继续铺新评论"，但**配额与报告契约里没有体现**）。
  2. 跟进的**形态配额**应与主评论**分开算**：楼中楼允许更短（≤40 字）、允许纯反应（`哈哈`/`我也是`），因为**那里本来就该像聊天**。
  3. ⭐ 引导"个人经历"在这里出现（F1 的正解）：跟进时优先"**我上次说的那个 + 我也遇到过**"，而不是解释观点。
- **预期解决**：**F1**（个人经历最自然的发生地）、**F3**（接话不需要判断式收尾）。

### N8 · 熟人小册：关系只记"回复过我的人"，且严格限量

- **来源**：MaiBot **A_Memorix** 的"实体/关系向量"（默认关闭，【①原文】）+ Pallas-Bot 的"**人物观察**"（【①原文】）。**两家都在做"了解某个人"，我们要做的是它的极端裁剪版。**
- **机制**：我们没有固定对话对象，所以"关系"不能是数据库，只能是**一张小卡片**：谁回过我、我上次说了什么、他是什么语气。
- **落地**：
  1. 新增**可选**资产 `relations.md`（≤20 行，一行一人）：`uid · 昵称 · 我上次的评论(rpid) · 他的语气(友好/抬杠/提问) · 只回一次`。
  2. 只服务**楼中楼**（N7），**绝不用于"装熟"**：不叫昵称、不提"上次你说过"（除非同一话题、同一楼）。
  3. 写入条件极严：**只有他先回复我**才建档；被骂/引战直接 `retired`，永不再回。
- **预期解决**：**F1**（有具体对象时"我"自然出现），同时通过严格限量**规避 §6.4 的装熟风险**。

### N9 · 来源与纠错通道：承认"会见闻记错"，留一条修正路径

- **来源**：MaiBot FAQ【①原文】"记忆为什么会把人物或主客体记反" → 处理办法是"**先查来源消息**，确认原始表达是否有歧义，再检查抽取/写回模型；可通过**反馈纠错或删除后重新写入**"。
- **机制**：官方明确承认记忆会错，并把"来源 + 可纠错"作为产品能力，而不是假设记忆是对的。
- **落地**：
  1. 见闻库每条**必须带** `sourceBv` + `sourceQuote`（视频里那句话的原文），没有来源的条目**不允许 active**。
  2. `duty.md` 已有"不确定的事实别编"——把它升级为**结构性约束**：写评论时若引用了见闻库条目，**必须能指到 `sourceBv`**。
  3. 加 `corrections.md`：一旦发现某条见闻是误读（评论被反驳/自己发现），**原地标记 retired 并写一行原因**，禁止删了重记同样的错。
- **预期解决**：**F5**（把误读的梗当社区共识写出去，是最"不像人"的一种错）。

> **落地优先级建议**：N2（表达库，治 F5 最狠）→ N6（生命周期，治 F4 最狠）→ N1（决策拆分，治 F2/F3 的结构因）→ N4/N5（状态与退避，便宜且立刻见效）→ N7/N8（楼中楼与熟人，治 F1）→ N3/N9（闸门与纠错，护栏）。

## 6. 不该抄的：会破坏"公开短文本"约束的手法

判据统一用一条：**这个手法需要"不可撤回"或"多轮上下文"才能成立吗？** 需要，就不能抄。逐条给理由。

### 6.1 🔴 分段发送 / 连发短句（MaiBot `[response_splitter]`）

- **手法**：【①原文】`max_length=512`、`max_sentence_num=8`、`max_split_num=3`，把长回复拆成多条发，"更像真人刷屏"。
- **为什么不抄**：群聊里"连发"是**在场**的证据；在 B站评论区，**同一个视频下连发多条**等于刷屏——我们 `duty.md` 已经明确"同一个视频只留一条评论、不刷屏"，这是平台红线也是账号风险。而且**不可撤回**：一句话拆错了、顺序错了，没有"补一条纠正"的机会，只会留下两条半截话。
- **替代**：把"多条"的丰富性压进**一条**里的**一个落点**（persona 已有"只抓一个具体的点"）。

### 6.2 🔴 生成错别字（MaiBot `[chinese_typo]`）

- **手法**：【①原文】`error_rate=0.01`、`min_freq=9`、`tone_error_rate=0.1`、`word_replace_rate=0.006`，还配 `enable_correction_quote`（**打错再补一条纠正**）。
- **为什么不抄**：这套机制**完全依赖"能补一条"**——错字没关系，因为下一句可以"啊打错了"。我们**没有下一句**。错字会永久挂在这个账号名下，而公开评论区里"形近字/同音错"是**判定 AI 或水军的高频特征**（【③推断】，但与 persona-whale.md"抗 AI 味"的目标方向一致）。
- **替代**（重要区分）：**"不完美"要来自语法，不来自错误**。允许 `半句`、`省略号`、`嗯`/`诶`/`啊这`、`话说一半`（persona「活人感」第 2、3 条已有）；**禁止**错字、错别字、把专有名词打错（后者会被当"根本没看"）。
- ⚠️ 顺带一条：`min_freq=9` 这个设计（**只对常见字制造错字**）本身很聪明——它说明 MaiBot 也知道"生僻字错一眼假"。我们可以把这个思路迁移到**别的地方**：**只在"高频口语词"上做省略/模糊**（"就那样吧"），不在**事实性名词**上含糊。

### 6.3 🔴 长回复 / 多段结构（MaiBot 允许 512×3）

- **为什么不抄**：我们硬上限 **100 字**，且 `duty.md` 明文"**别为'更像人'而扩写**"——热评中位 19–33 字，`封面能不能好好做？` 9 个字 4424 赞。长 = 测评腔 = F5。
- **注意**：MaiBot 那条 `reply_style` 里其实写着"**回复尽量简短一些**"（【①原文】），它是**允许长**但**引导短**；我们要反过来——**结构上不允许长**（lint 硬门），不靠引导。

### 6.4 🔴 装熟 / 关系记忆滥用（A_Memorix 关系向量 + 人物观察）

- **手法**：【①原文】建"实体—关系"向量（默认关闭）、Pallas-Bot 的"人物观察"，用来"永远都在更加了解你"。
- **为什么不抄**：**"了解你"需要"你"**。我们的场景里没有稳定对话对象，只有**一次性的、公开的、可能是陌生人的**观众。对陌生人说"上次你说过…""你不是喜欢…吗"是最典型的 OOC 事故，而且**公开可见**（不是私聊的尴尬，是当众的尴尬）。
- **可用的极小版本**：只有 N8（`relations.md`，≤20 人，**只对先回复我的人**，不叫昵称、不提旧事）。**超出这个范围的一切"关系感"都不要。**

### 6.5 🔴 人格随机切换（MaiBot `multiple_reply_style` + `multiple_probability`）

- **手法**：【①原文】按概率（0.1~0.3）临时注入一条备用风格，"想玩人格随机切换"。
- **为什么不抄**：我们的失败项里有一条是 **F4「每轮不像同一个人」**。人格随机切换**直接加重**它。MaiBot 之所以能玩，是因为群聊**连续多轮**里"偶尔崩一下"是可爱的；我们**每一轮都是独立的一次公开露面**，没有"平时"作对照，切换只会显得像**两个人共用一个号**。
- **替代**：要"不一样"，改**状态**不改**人格**：`mood`（今日状态）+ **时段**（N4）+ **能量档**（N5 的 skipStreak）。三者都**在同一人格内**波动。

### 6.6 🟡 主动插话 / 强行接话（MaiBot `behavior_style` 的群聊逻辑）

- **手法**：【①原文】"群里聊到感兴趣的内容再插话"——**在场者**的合理行为。
- **为什么不抄**：B站评论区**没有"场"**。一条评论是一条独立公开留言，没有冷场要打破、没有话题正在流动。所谓"主动接话"在我们的场景里等于**对着空气搭话**，写出来就是"空泛捧场"（`不错`/`学习了`/`太强了`）——`duty.md` 已经判定"**不如不评**"。
- **替代**：把"主动"从**说话**挪到**选题**（选材兴趣漂移，见 §4 第 15 行）。

### 6.7 🟡 贴表情包 / 偷表情（MaiBot `[emoji].steal_emoji`、`max_reg_num=64`）

- **为什么不抄**：B站评论**没有图片表情包**，只有 `[doge]` 这类文本 emoji，而且 persona 已定"一条最多一个"。`steal_emoji` 我们无对象可偷。
- **可迁移的只有"容量与淘汰"这一层**（→ N6），**不是**"贴图"本身。

### 6.8 🟡 长上下文注入（MaiBot `max_context_size=40`、滚动摘要 6000 字）

- **为什么不抄**：**单轮无上下文**是硬约束。把"我最近说过什么"整段塞进 prompt 有两个反效果：
  1. 模型会**模仿自己最近的说法**（这正是 F2/F4 的机制：越喂越像）；
  2. 会诱导它**回应不存在的前文**（写"接上条"之类）。
- **替代**：只喂**结构化的"欠哪种形态"**（宿主算的 3 个数），不喂**原文**。persona 里"写之前先看账本里自己最近 3 条正文"这条**要改成给宿主算好的摘要**（起手词/形态/收尾类型的标签），而不是三段原文。

### 6.9 🟡 关键词反应（MaiBot `keyword_reaction`）

- **手法**：【①原文】命中关键词/正则 → 追加一段"反应提示"作为生成指令。
- **为什么不抄**：方向相反。我们的"不看清单 / 红线 / 判重表"是**否决器**（命中就跳过），而关键词反应是**触发器**（命中就开口）。在短文本场景里，"看到关键词就发"必然产出模板句（F2 的另一个源）。
- **可迁移**：把"关键词"用在**否定方向**——`lint` 里已经有"禁骨架/禁起手词"，可以扩展成**禁用短语库**（从自己历史失败评论里提炼，persona「别这样写」那 4 条就是雏形）。

### 6.10 一句话总结"不该抄"

> **凡是需要"下一句"才能成立的手法，我们都不能抄**——分段、错字纠正、连续追问、装熟、人格切换，本质上都是"用后续动作修补前一句"。我们的每一句都是**终稿**，所以只能抄**"一次成型"的手艺**：选材、落点、语料、状态、容量与淘汰。
