## 0. 四条投诉 → 四个改动包

| # | 用户原话 | 根因（审计结论） | 改动包 |

| 1 | 概览页不实时 | 概览唯一数据源是账本，而账本是 agent **轮末批量写**；运行中真实进度只存在 `lib/live.js`，概览不消费；4 路独立轮询无 seq/abort；失败不显形 | **R：单一实时信封 + SSE** |
| 2 | 没有主动尝试去回复其他人的评论 | 章程把接话写成「可选动作」，**不留任何"评估过"的痕迹**；宿主/报告/账本都不记扫描；活动页还把接话误标成「跟进回复」 | **P：接话扫描闭环** |

| 4 | 页面杂乱、布局混乱、看不到主体 | 7 个同权页面 + 概览 7 张同权卡 + 人设 8 子页签 + 设置超长表单；配额第 6 块成孤儿瓦片 | **U2：7 页签 → 5 页签 + 每页单一主问题** |

## 1. U2 · 信息架构（7 → 5）

### 2.2 `GET /api/bili-fenshen/stream`（SSE，新）

复用 `lib/api.js` 现有 SSE 骨架（上限 4 连接 / 15s 心跳 / `closeSse()`）：

| 帧 | 内容 | 何时 |
|---|---|---|
| `{type:'hello', seq, serverTime}` | 连接确认 | 建连 |
| `{type:'overview', seq, dataUpdatedAt, data}` | 完整信封 | 建连；文件变更（debounce 250ms，最小 800ms）；轮次 start/end；replyTick 后；配置/开关保存后 |
| `{type:'tick', seq, round:{elapsedMs,phase,stats}, quota:{perRound}}` | 轻量 | 运行中每 1500ms |
| `: ping` | 心跳 | 15s |

### 2.3 客户端协调器（`useRealtime`）

- 主通道 SSE；`seq` 单调守卫；`onerror` → 关流、降级轮询（运行中 2s / 空闲 10s）。
- 轮询用 `AbortController`，旧请求先 abort；响应按 `seq` 丢弃过期的（解 A4）。
- 刷新触发：挂载 / `visibilitychange` 可见 / `window.focus` / SSE 帧 / `onRun|onStop|onToggle|onLoggedIn` 后。
- 新鲜度：`ageMs = Date.now() - Date.parse(dataUpdatedAt)`；页头徽标 `>15s` 黄「数据 18s 前」、`>60s` 红「数据 2m 前·正在重连」，`error` 非空时也显形（解 A3）。

### 2.4 服务端实现约束

- 新建 `lib/realtime.js`：`createOverviewHub({ getOverview, watchPaths, now, debounceMs, minIntervalMs })` → `{ view(), publish(), close() }`；仅纯逻辑 + 注入 IO，可单测。
- 新建 `lib/overview.js`：`buildOverview({ cfg, state, events, liveSnap, presence, account, health, now })` 纯函数（把 `index.js:908-949` 抽出来）。
- 新建 `lib/round.js`：`roundAccounting(events, roundId)` 与 `presenceFrom(events, now)`、`lastRoundFrom(events)`。
- `state.json` 双写修正：`lastRunStartedAt`（本轮开始）与 `lastRunAt/lastCode/lastDurationMs`（上一轮结束）分开。
- 对历史轮次不判违规：`state.replyScanSince` = 首次安装本版时间。

## 3. P · 接话扫描闭环（前后端契约，冻结）

**核心**：把接话从「可选动作」改成**每轮必须做的扫描**；发不发仍自由。

### 3.1 章程（`prompts/duty.md`）

1. 「一轮要做的事」加 `3.5 接话扫描（每轮必须做，0 工具成本）`：从已拉到的热评里评估 ≥1 条，结论写成机器行；没有可接的也要写「候选 0 / 全部不接 + 理由」。
2. 「接话纪律」重写：可接三类 = 能答清的提问 / 被逗到共鸣 / **轻互动**（被夸、被逗、道谢、生日祝福）；候选优先级 = 有 `reply_count>0`、含问号、有具体信息；**扫描不占 ≤20 工具预算，接一条只多 1 次 `bili_reply`**；去重 = 同 BV ≤1/轮、同一 target rpid 永不重复、同一用户 7 天 ≤1。
3. 报告契约加机器行：`接话扫描：候选 3 → 接 rpid 321560862800（666设计师）` 或 `接话扫描：候选 0（热评全在站队，不接）`；`动作：` 行里接话段**必须在最后**。
4. 记账契约加 `reply-scan` 事件；`reply-out` 的 `kind:"proactive"` 约定不变。

### 3.3 宿主

- `quotaFromLedger` 增记 `replyScans` / `proactiveSkipped`；`round-end` 追加 `{ replyScans, proactiveReplies, proactiveSkipped, proactiveMissing }`。
- `roundAccounting`：`proactiveMissing = views>=1 && scans==0 && posted==0`（且本轮开始 ≥ `replyScanSince`）；缺失时写 `note` 并在信封 `round.lastRound.proactiveMissing` 暴露。
- `proactiveTargetsFromLedger(events, {days:14})`（`lib/replies.js`）→ 注入「已接话清单」。
- `parseProactiveScan(text)`（`lib/report.js`）：解析 `接话扫描：` 行 + 动作行里的 `接话（rpid N）：` 段；**`parseCommentAction` 先剥离接话段**（修解析地雷）。
- `backfillFromReport` 补 `reply-out(proactive)` 与 `reply-scan`（`source:"report"`）。

### 3.4 UI

- 概览「接话」卡：`今日 1 · 上轮扫描 1 → 接 1`；不接时 `上轮扫描 1 · 不接（理由）`；未扫描时红色「未扫描」。
- 活动页：`reply-out` 按 `kind` 分「接话 / 跟进回复」；新增筛选「接话」「接话扫描」；`stageOf` 增 `scanned/proactive`，`repliedBack` 只看非 proactive。
- 概览运行详情：轮末摘要显示 `接话：扫描 N / 接 M`。
- 配额卡「今日 / 本轮」分栏，语义写清。

- `bili_reply` docstring 增「主动接话：rpid=对方一级评论 rpid，root 留空」示例。

## 4. U1 · 视觉与层级（照宿主）

- **每页页头**：`pageTitle` 20/28/500 + `pageIntro` 13/20 tertiary + 右侧 ≤2 个主操作；页面唯一 `h1`。
- **概览状态条**：一行 pills（运行/自动值班/下一轮/数据新鲜度），不再重复值班卡里的 4 个事实。
- **今日产出**：一条「今天：看 2 · 赞 2 · 评 1 · 接话 1 · 动态 0」数字带 + 最近 3 条说过的话（正文 + BV）。
- **卡不再同权**：P0 卡（运行/今日产出）用 settings-card 材质 + 16 圆角；次要信息收进一行摘要 + 可展开。
- **配额**：6 项改 3×2 网格（或一行 6 个等宽瓦片），日累计/本轮分列；不再出现孤儿瓦片。
- **设置行式化**：`label + 说明` 左、控件右，行高 60；三段子页；底部脏标记保存条。
- **字号/圆角白名单**：11/12/13/14/16/18/20/24；4/8/12/16/20/28；18 处字号吸附、3 处幽灵类名（`.bf-card-foot` / `.mono` / `.bf-grid-5` 孤儿）。
- **错误与空态**：轮询失败必须显形；空态用宿主式说明，不用虚线框。
