# 主动接话 + 已看过清单 —— 设计文档

- 日期：2026-10-27
- 状态：已确认（用户拍板四项：接话范围=只接已拉到的热评；配额=2 条/轮；接话收到的回复也要回；已看过=宿主注入硬判重）
- 上游：本文件独立成篇；章程/记账/控制台的既有契约不变，只做增量和两处收口

## 1. 背景与目标

用户两点诉求（原话）：

1. 「还缺乏一个主动回复别人评论的能力」——现状章程「跟进纪律」只允许回**别人回复我评论**的跟进；
   主动去接别人评论的话（楼中楼露面）没有被授权。
2. 「在每一轮读信息源的时候，之前看过的就直接跳过就是」——现状判重全靠 agent 自觉读 `seen.md`，
   重复看老视频的根源就在这层不可靠。

关键事实（侦察结论）：

- `bili_comments` 是评论的**硬前置**（章程第 3 步），每条热评都带 `rpid`；`bili_reply` 带 rpid 即进楼中楼。
  ⇒ 主动接话**不需要新 MCP 工具**，缺的只是章程授权 + 配额 + 记账口径。
- 宿主账本 `ledger.jsonl` 已记录 view/like/comment/dynamic/skip/reply-out（全部带 BV 号）。
  ⇒ 「已看过」可以由宿主算好注入本轮参数，命中即丢、零工具调用。
- 宿主 `replyTick`（5 分钟一轮）已把回复通知落成账本 `reply-in` 事件；
  归属函数 `roundIdForReply` 目前只拿 **comment** 事件的 rpid 匹配——接话（reply-out）收到的回复归属不到轮次，需要收口。

## 3. 功能 1 —— 主动接话（回复别人的评论）

### 3.1 配置

- 新增 `replyOthersPerRound`（zod natural，默认 2；`lib/config.js` FIELDS + 'number'）。
- 控制台：设置 → 配额组加「每轮主动接话」；值班页配额条加一块「主动接话」（今日计数 vs 每轮上限）。
- 顺带修一个旧账：`buildOverview.quota` 从未输出 `replies`，「跟进回复」块一直是空的——
  `quotaFromLedger` 增记 `replies`（当日全部 reply-out）与 `repliesProactive`（其中 kind=proactive），
  「跟进回复」块显示 `replies - repliesProactive`。

### 3.2 章程（duty.md）

- 「一轮要做的事」执行动作加一条：**接话**（`bili_reply` 带 rpid，只接本轮已拉到的热评）。
- 新增「接话纪律」节（跟在跟进纪律之后）：
  - 只从**本轮已拉到的热评**里挑（bili_comments 已返回 rpid）；拿不准就不接，不额外翻楼中楼。
  - 值得接的就两类：能答清的提问 + 被逗到/共鸣（一句俏皮话收住）；沿用评论纪律
    （≤80 字、收在情绪/梗/问题、不吵架不阴阳、复述要再创作）。
  - **同一视频最多接 1 条**（2 条/轮的配额天然跨视频）；同一个人同一话题只接一次。
  - 到量就停；接话是可选项，没得接就不接（与「配额是上限不是任务」同款）。
- 报告契约动作行扩展：`动作：评论（rpid…） + 接话（rpid…）：正文`。

### 3.3 记账与判重表

- `reply-out` 账本行加 `"kind":"proactive"`（跟进回复不带）；parent = 对方评论 rpid。
- 判重表动作枚举加「接话过rpid」。

## 4. 功能 2 —— 已看过清单（宿主注入，命中即丢）

- 新增纯函数模块 `lib/seen.js`：`seenListFromLedger(events, opts)`——
  取所有带合法 BV 号的事件，**最近 14 天**、按时间新→旧去重、**上限 250 条**；
  非法 BV / 无 t 的事件忽略。窗口与上限可注入（测试用）。
- `buildDutyPrompt` 本轮参数新增一行：
  `已看过清单（宿主从账本算好，最近 14 天）：BV…、… —— 命中的候选直接丢：不读信息、不读字幕、不点赞不评论、不进报告、不记判重表（账本里本来就有）。`
- 章程第 2 步「判重」改为两层：
  1. **硬判重（宿主）**：拉到候选列表（搜索结果 / UP 投稿列表 / 热门榜）先按注入清单过滤，命中直接丢，一个工具调用不花；
  2. **档案判重（seen.md）**：照旧追加维护，负责 14 天以前的历史；读不到时维持原纪律（本轮不发评论/动态）。
- 顺延逻辑白捡：UP 主最新投稿若全部命中清单 ⇒ 不读任何视频就知道顺延下一位。

## 5. 接话的回环（跟进纪律收口）

- 章程「跟进纪律」改写：
  - **轮次开始先查一次** `bili_received_replies`——有人等我回就先回，优先级高于铺新评论；
    发出去的评论/接话，发完 30–60 分钟内也回查一次（原有条款保留）。
  - 「我的话」= **我发的评论 + 我的接话/回复**（判重表里记了 rpid 的都算）——只回直接回复到我这些话下面的人。
  - 防连剧：同一楼中楼我最多说两句（接话算第一句、跟进算第二句），同一个人同一话题只回一次——
    对方再回就不接了（拿不准就不回 ✓）。
- 宿主 `roundIdForReply` 收口：从 index.js 移到 `lib/replies.js`（纯函数、可单测），
  匹配面从 comment 事件扩到 **comment + reply-out** 事件的 rpid（都取近 7 天），接话收到的回复正确归属轮次。

## 7. 不做的事（YAGNI）

- 不给 MCP 评论返回补子回复 rpid（钻楼中楼）——用户已选「只接热评」，将来要开再补（小改）。
- 不让宿主代拉内容源（架构不动，agent 仍自己拉，宿主只给判重弹药）。
- 不做 reply-in 未处理量的注入提示——轮首查 `bili_received_replies` 一次已够可靠。
- 已看过清单不做按分区/UP 的再细分——平铺 BV 列表就是最小可行。
