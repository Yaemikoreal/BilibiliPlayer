## 0. 一页纸结论

**问题不是"人设写得不好"，而是"人设不是一个模块"。** 它现在是一个字符串：可填正文或文件路径，读出来原样拼进值班 prompt，没有任何结构、素材、状态、校验、版本与归因（审计 §0/§1）。因此三件事同时发生：

1. **规则在稀释**：同一批评论纪律在人设、章程、宿主 prompt 模板三处双写并已漂移（审计 §4.3）——加规则只会变成第四处。
2. **素材是空的**：247 条真人语料只能人工抄进正文；人设里"写前看账本最近 3 条"全靠模型自觉；没有"私人经历/见闻"可召回 → 实测 5 条评论 **0 条个人经历、0 条疑问**（10-25 数据）。
3. **效果不可归因**：账本/报告/state/诊断零人设字段、prompt 不落盘（审计 §5）→ "人设有效"全靠人肉读日志。

**本设计的答案**：把"人设"升级为一个**有数据模型、有编译期、有运行状态、有语料库、有质量门、有控制台、有归因**的独立模块（Persona Engine），并用**八条机制**落实"活人感"：

| # | 机制 | 解决的失败 | 证据 |
|---|---|---|---|
| M1 | **见闻库（lorebook 等价）**：关键词触发、按需读取、冷却防重复 | 0 条个人经历 / 编造事实 | 酒馆 World Info；真人经验分享 27.9% |
| M2 | **状态与连续性**：今日心情/精力/时段 + 最近 3 条自己说过的话 | 5 条整齐得可怕、跨轮不像同一个人 | 10-25 五条同型；`persona L23-27` |
| M3 | **形态欠账**：宿主算出"最近 5 条欠哪种形态"，写进 prompt | "每 5 条至少 1 条疑问"这条规则从未被执行 | `commentsPerRound=2` 时一轮凑不齐 |
| M4 | **最后一公里注入**：3 行约束 + 6 类收法轮换（**不给具体句子**） | 关键约束埋在 7k 字章程之前；给"标准答案"会 5/6 收敛 | 酒馆 Author's Note；GitHub 样例实测 |
| M5 | **质量门**：发布前确定性 lint（P0=落点/自足/再创作），不过重写一次，再不过就不发 | 判断式收尾 3/5；17× 与 ∞ 级 A/B 差异 | 1787 vs 1 赞、153 vs 0 赞 |
| M6 | **决策前置与沉默退避**：先定"发/不发"，再写正文；连续跳过就降能量 | 边判边写 → 判断式收尾、凑数发 | MaiBot `behavior_style`/`no_action_backoff` |
| M7 | **语料库 + 生命周期**：按形态分桶的真实热评，反比加权抽取；容量/冷却/退役 | "语感不对"、"欠形态名却不会写"、越用越旧 | Pallas-Bot 表达库；MaiBot `max_reg_num`/`do_replace` |
| M8 | **时段与作息**：把"现在几点"算出来，作用于长度与形态 | 每轮温度一样 | MaiBot `talk_value_rules` |

**参考来源三路**（覆盖度自检见 §2.5）：酒馆提供**结构与位置**（§2.1）；MaiBot / Pallas-Bot 提供**"要不要开口"与真实语料库**（§2.5）；GitHub 去 AI 味与角色卡写作样例提供**可机检的格式判据**（§2.5）。三路合计 27 条机制，采纳/改造 20 条，**明确拒绝 10 类**（含"生成错别字""长回复""绝对零度白描"等会直接推翻我们基线的做法）。

**同时明确"不做什么"**（防止下一轮又把文档加厚）：不注入随机错别字/乱标点；不加长度规则；不把 AI 检测器分数当门；不做 best-of-n；不把"没进热评"当压审。理由见 §2.4 与调研 §7。

**关键取舍：v2 不是"更多提示词"，而是"更少提示词 + 更多机制"。** 酒馆调研给出两条反转结论：① **常驻条目彼此竞争**，每多一条，其余每条的实际影响力都下降（attention dilution）；② 短评论没有多轮历史，预算不紧张，**瓶颈是注意力稀释而不是上下文长度**。所以人设编译结果从 5,244 字符**降到 ≤3,000 字符**，把行为约束交给"示例 + 最后一公里 3 行 + 质量门"，而不是继续往正文里加规则。

**成本与收益**：人设 5,244 → **≤3,000 字符**（人看的解释移进 `creatorNotes`，行为细则交给机制），章程瘦身 ~1,500 字符，整轮 prompt 从 14,214 → **约 10,200 字符（−28%）**，同时**多出**状态/见闻索引/示例/尾注四层信息。新增运行时代价 = **每轮 +1 次 MCP 工具调用**（lint），在现有"≤20 次/轮"预算内。

**落地**：6 个阶段、约 9–11 个工作日；每阶段可独立回滚；P0/P1 不改行为、只搭骨架（有 prompt 快照测试兜底）。

## 2. 调研结论：抄什么、不抄什么

### 2.1 酒馆（SillyTavern）能抄的六条机制

酒馆的价值不在"角色扮演"，而在**它把"人设"拆成了多个可独立编排的槽位，并规定了每个槽位的位置语义**。调研已抓到规范原文（[报告](../../research/2026-10-26-tavern-persona-research.md) §1–§2），可迁移的六条：

| 酒馆机制 | 规范原文/机制要点 | 我们的对应物 | 判定 |
|---|---|---|---|
| **角色卡字段**（description / personality） | `description` **"always included in the prompt"**；`personality` 只是摘要 | `identity` + `taste` + 口吻**事实**（句长上限、口癖、禁用词） | ✅ 可用，但**压缩到 ≤1,600 字符** |
| **`creator_notes`** | 原文 **"MUST NOT 进 prompt"**（元数据与人设内容硬隔离） | `creatorNotes`：配比理由、日志复盘、语料统计、迁移说明 | ✅ 直接抄 —— 现在我们 1/4 的正文是写给人看的，正该搬走 |
| **`mes_example`** | 按 `<START>` 分块，**超预算逐块挤出**；示例位置越靠后影响越强 | **示例库**：按形态打标签，每轮 1–2 条，**放在末尾附近** | ✅ 改造后可用（按"评论区形态"分，不按对话分） |
| **`first_mes`** | 原文：开场白是**最强的风格与长度锚点**，胜过任何字段 | 我们没有开场白，但**结论可搬**：把"最想被模仿的那条评论"放在离生成点最近处，而不是埋在长描述中间 | ✅ 只借结论 |
| **World Info / Lorebook**（keys/constant/order/budget/Outlet） | 全部机制发生在**编译期**，只能匹配已在上下文里的文本；**Outlet 宏在角色卡字段里无法展开**，因为这些字段被提前解析 | **见闻库**：索引常驻 + 正文按需读（§7.1） | ✅ 改造后可用；不能编译期召回，理由见 §7.1 |
| **Author's Note / `@D` 深度注入** | 原文：**"越靠近 prompt 底部，影响越大"**；可选注入 role（user 服从度更高）；**只改行为、不改事实** | **最后一公里块**（§7.4） | ✅ 最值得照搬；但我们是单条 user 消息，**role 不可选**（见 §7.4 注） |
| `post_history_instructions` / `system_prompt` 覆写 | 卡级覆写主提示词 / 最后裁决位 | 用"位置"表达（末尾块），不用内容覆写 | ✅ 借位置语义 |
| `scenario` / `first_mes` 内容 / `alternate_greetings` / User Persona | 多轮扮演、开场白、对话对象 | 无 | ❌ 不适用 |
| 多轮记忆 / 关系演化 | 依赖"有下一轮" | 退化为"最近 3 条负向约束 + 今日状态"（§7.2） | ⚠️ 改造后可用 |

**两条最重要的反转（直接改变本设计）**：

1. **"事实放常驻，行为放末尾"**：想让它"稳定知道某事"（身份、口味、红线）必须常驻；想让它"这一句按某种方式写"（长度、落点、形态）放末尾。把行为规则写进常驻，等于稀释掉事实。
2. **常驻要少而硬**：常驻条目互相竞争。原研究给的上限是"常驻 ≤3 条硬规则"，其余靠示例与机制。这解释了为什么现在 5,232 字的人设对行为约束力反而不如一篇 300 字的卡——**不是内容不对，是互相打架**。

### 2.2 其他主流平台的取舍

| 平台 | 值得借鉴 | 不适用 | 结论 |
|---|---|---|---|
| Character.AI | 角色定义 + 示例对话 + 轻量记忆 | 以"陪聊"为目标，鼓励长回复 | 只借"示例 > 形容词" |
| Janitor AI / Chub | 结构化角色卡 + 可分享的卡生态 | 依赖多轮上下文与越狱式设定 | 只借"卡即数据" |
| Risu / 酒馆 | lorebook 分层、预设 prompt 编排 | 依赖前端模板引擎 | 借"分层与位置" |
| 星野 / 猫箱 / 筑梦岛 | 关系状态、主动发起、记忆面板 | 私聊、情绪陪伴 | **不借**：我们不需要"关系"，需要"这个人今天的状态" |

> 一句话：**酒馆教我们"怎么组织人设"，不教我们"怎么说话"**。说话的手艺来自本项目的语料基线（§2.3）。

### 2.3 本项目内部实证（比外部调研更硬）

| 观察 | 数字 | 结论 |
|---|---|---|
| 同一件事、同一长度区间，收尾不同 | 收在情绪 **1787 赞** vs 收在事实 **1 赞**；场景复现 **153 赞** vs 二手转述 **0 赞** | **落点**是唯一有 17×/∞ 级证据的因子 |
| 长度与点赞 | 9 字 `封面能不能好好做？` = 4424 赞 | 长度**不是**指标，禁止再加长度规则 |
| 真人基线（247 条） | 中位 27 字；句号 10.9%、问号 12.6%、表情 **41.7%**、无逗号 35.6%、分号 2.8%、含"我" 32.8% | 可直接当 lint 阈值来源 |
| 我们的 5 条（10-25） | 0 疑问、0 个人经历、0 表情、4 条"细节+判断" | 缺的是**素材与落点**，不是文笔 |
| 规则遵循 | "每 5 条至少 1 条疑问"从未被满足（`commentsPerRound=2`） | 规则必须**变成数据**（欠账）才可能执行 |

### 2.4 四条反直觉结论（直接写进"不要做"）

1. **长度不是指标**：真人双峰分布（≤15 字 27.9%，>60 字 24.3%，41–60 仅 10.9%），但 41 字的 1787 赞与 15 字的 1 赞并存。→ 只保留"不要为像人而扩写"这一句，**不设长度区间门**。
2. **人味是可学的省略分布，不是注入的方差**：无逗号 35.6% 但句号仅 10.9% 是**稳定规范**，不是随机错误。→ **噪声只能来自"省略"，不能来自"错误"**。
3. **AI 检测器不能当门**：可被同义复述击穿、对非母语/简省表达有偏置、发明者已弃用统计特征；在 27 字上统计无效。→ 只做"退化告警"报表，不进决策。
4. **best-of-n 与"逐条自检"已被日志证伪**：为一条 19 字评论写 5 稿、reasoning 占日志 85%（`log-findings` §2.7）。→ 质量门只允许**改一次**，不做 n 选 1。

| GitHub mengke 信息缺口 | "不许说满"（真人的 `我不行了` 是故意留缺口） | 只能模型自评 → L2 一问 + P5 不写具体句，P2 |
| GitHub mason 具体物 | 见闻要"够具体"，反常识细节优先 | 可做较弱 L0（"entry 必须有 1 个具体名词/数字"），P2 |

#### 2.5.3 **明确拒绝**（10 类，写进文档防止后人加回来）

| 来源 | 做法 | 拒绝理由 |
|---|---|---|
| MaiBot `response_splitter` | 分段发送/连发短句 | B站一条评论就是一段；连发 = 刷屏特征 |
| MaiBot `chinese_typo` | 生成错别字 | 与"噪声只能来自省略、不能来自错误"直接冲突；损自足性 |

#### 2.5.4 覆盖度结论

- **结构层**（怎么组织人设）：酒馆 → 已完整吸收（字段、位置、示例、见闻）。
- **机制层**（怎么让它是"活人"）：MaiBot/Pallas → 补上原设计**最大的三块空白**：① **要不要开口**（决策前置）② **真实语料库**（不是"欠形态名"而是"欠句子"）③ **生命周期**（容量/淘汰/冷却，防"越用越旧"）。
- **格式层**（怎么写才不被模型学坏）：GitHub 样例 → 补上三条**可机检的人设格式判据**（红线三件套、矛盾 X vs Y、词频 ≤3），并**修掉了原设计里一处会自我收敛的写法**（P5 给具体句子 → 改分类手段表）。
- **反向验证**：三路里对我们最有价值的一条，恰恰是**否定式**的——"别给出具体句子"解释了 10-25 五条同型；这条以前我们只在日志里看到现象，没有机制解释。

## 3. 设计原则（七条，评审时的判据）

1. **单一事实来源**：同一条规则只能活在一个地方。风格规则归**人设卡**；流程/契约/配额归**章程**；本轮例外归**开关**。三处双写必须收敛（§4.3）。
2. **素材优先于形容词**：能写"我上周在宽甸吃婚宴吃晕了"，就不写"要口语、要有个人经历"。形容词对模型是噪声，素材是信号。
3. **分层与位置**：**事实常驻**（身份/口味/红线）→ 本轮（状态/欠账/最近 3 条）→ **行为末尾**（3 行提醒）。位置决定权重，越靠后越强；常驻条目互相竞争，**只放"缺了必错"的**。
4. **规则变数据**："最近 5 条欠什么形态"由宿主算出来，而不是让模型自己数（模型数不对，日志已证）。
5. **可判定性分层**：代码能判的（长度/标点/词表/收尾正则/重复度）交代码；只能语义判的收敛成**二元问题**；统计指标只在发布后聚合。**能拦的必须拦在 `bili_reply` 之前**。
6. **可归因、可回滚**：每轮记录 `personaId@version#hash`；prompt 落盘快照；人设版本可 diff/回滚；改坏了不影响正在跑的一轮。
7. **默认就好用**：装机即有人设（预设卡），控制台可一键切换/试用/回滚，不需要用户先去 README 找路径。

## 4. 总体架构

### 4.1 模块边界

**结论：做成插件内的独立子模块（不是独立 npm 包）。** 理由：它与值班轮（prompt 编译）、账本（状态派生）、控制台（编辑/预览）、MCP 工具（质量门）四处强耦合；拆成独立包会立刻产生循环依赖与版本对齐成本，而它并不需要被第三方复用。

```
dsh-plugin/
├─ lib/persona/              ← 新：人设引擎（唯一对人设负责的代码）
│  ├─ index.js               门面：load / compile / save / preview / lint / state
│  ├─ card.js                schema 校验、默认值、版本迁移（v1 文本 → v2 卡）
│  ├─ store.js               读盘/原子写/版本快照/预设与用户态的合并
│  ├─ compile.js             卡 → 分层 prompt 块（含预算与省略策略）
│  ├─ sample.js              示例/反例轮换（确定性 seed + 冷却）
│  ├─ lore.js                见闻库索引生成、命中建议、冷却记账
│  ├─ state.js               今日状态派生、形态欠账计算、最近 N 条正文
│  ├─ budget.js              字符/token 预算与 argv 上限守卫
│  └─ legacy.js              personaPrompt（正文/路径）→ 兼容注入
├─ lib/style.js              ← 新：风格判定纯函数（JS 侧，控制台/审计/一致性测试用）
├─ prompts/persona/          ← 新：内置预设卡

├─ prompts/persona-whale.md  ← 保留：v1 兼容 / 迁移来源 / 人类可读版（不进 prompt）
└─ test/persona.*.test.js    ← 新：卡校验/编译快照/预算/状态/门禁一致性
```

**为什么人设不塞进 `config.json`**：现在 `config.js` 是"扁平标量白名单"（`string|number|boolean|array`），塞一个对象要改整个白名单机制；而人设是**多文件 + 需要版本快照**的东西，放 `<家目录>/persona/` 更自然。config 只保留两个标量：`personaId`（预设 id，空=用文件）与 `personaLegacyPrompt`（旧字段别名，只读兼容）。

### 4.3 三层职责划分（收敛的关键）

| 层 | 回答什么问题 | 放什么 | 不放什么 | 位置 |
|---|---|---|---|---|
| **人设卡**（本模块） | **我是谁、我怎么说话** | 身份、口吻、品味、固定态度、红线、示例、见闻索引 | 流程、配额、工具用法、报告格式 | 注入在章程**之前** |

## 5. 数据模型：Persona Card v2

### 5.1 设计取舍

- **JSON 而非 YAML**：控制台可直接读写、可 JSON Schema 校验、可与 `config.json` 同构；不引入依赖。
- **只保留"评论区人格"需要的字段**：角色扮演专用的 scenario/first_mes/greetings 一律不收（§2.1）。
- **`creatorNotes` 不注入**：把现在 whale 里写给人的解释（配比理由、日志毛病复盘、语料统计）搬进去，省下的是真金白银的 token。
- **`loreIndex` 与 `lore` 正文分离**：索引（一行一条）进 prompt，正文按需 `read`（§7.1）。
- **红线可机检、且必须"三件套"**：每条红线写成 `{rule, why, instead}` —— 只写"不许"会让注意力被那个画面捕获（否定即粉红大象），所以每条都要给**正向替代**；同时带 `lexicon`/`regex` 供质量门直接判。
- **口吻写"语体特征"，不写逐字口头禅**：写"说话短、爱用反问"可以；写"每句带某某词"会被模型当"看到就用"，必然复读到腻（实测：示例里的固定梗会被逐字模仿）。
- **风格来源是语料库，不是形容词**：`expression-bank.json` 按形态分桶存真实热评原句，宿主按欠账抽样注入——"欠一个疑问"和"给三条真人疑问长什么样"是两件事。
- **`behaviorStyle` 独立成段**：把"何时开口 / 何时安静"从"怎么说话"里拆出来，让"发不发"先于"怎么写"被决定。

## 6. 编排：Prompt 编译器

### 6.1 五个块、位置与预算

编译是**纯函数**：`compile(card, { state, charter, switches, roundId }) → { text, stats }`。块的顺序即注入顺序——**位置本身就是设计**。

| 块 | 内容 | 预算（字符） | 位置 | 为什么在这 |
|---|---|---|---|---|
| **P1 常驻核心** | identity（≤350）+ taste（≤300）+ 语体**事实**与禁用词（≤350）+ redlines 三件套摘要（≤250）+ canon（≤250） | **1,500** | 人设块（章程之前） | 身份/口味/红线是**事实**：缺了必错，必须常驻 |
| **P2 见闻索引** | 一行一条 `id · keys · oneLine`（≤8 条） | **300** | 紧跟 P1 | 是"我有哪些经历"的事实性清单 |
| *(章程)* | 流程/契约/配额 | ~5,900 | P2 之后 | 工作手册 |
| *(本轮参数)* | 配额/内容源/开关 | ~1,300 | 章程之后 | 现有约定不变 |
| **P3 本轮状态** | 今日 mood/精力/**时段**/**沉默计数** + 最近 3 条自己说的 + **形态欠账** + **本地语感**（该视频评论区的形态分布） | **500** | 参数之后 | 越靠近生成点，模型越会把它当"当下" |
| **P4 表达库样本** | **同形态 3–5 条真实热评原句**（按欠账从 `expression-bank` 抽）+ 1 条反例 | **450** | P3 之后 | 借 `first_mes` 结论：**最强风格锚点放最后附近**；"欠句子"而不只是"欠形态名" |
| **P5 最后一公里** | 3 行：约束（**不写具体句子**）+ 6 类收法轮换 + 红线 | **250** | **prompt 最末尾** | Author's Note 的 depth 0 语义 |
| **合计** | | **3,000** | | |

**三条位置纪律**（来自酒馆规范，见 §2.1）：

1. **事实常驻、行为末尾**：身份/口味/红线进 P1；"收在情绪上""第一句要自足"进 P5。把行为规则塞进 P1，只会稀释身份。
2. **示例靠后、数量极少**：P4 只放 3–5 条**同形态**样本（不是混合 5 类）。示例超过 5 条会变成模板，评论区能看出同一个号在批量发（调研 §6.4；MaiBot 的候选池上限也是 5）。
3. **末尾位是竞争性资源**：P5 只允许 3 行，且**只写约束、不写具体句子**——给出"标准收尾 5 选 1"会让模型 6 句里 5 句收在同一格（GitHub 样例实测），这正是 10-25 五条同型的机制解释。**例外**：合规话术可以钉死（"AI 弄的号，官方不认识我"），因为那是内容不是创作路径。
4. **约束先于表达**：`behaviorStyle` 决定"发/不发"，然后才轮到 P3/P4/P5。**先判后写**与"边判边写"的输出骨架完全不同（前者不会长出"我先评价一下"）。

### 6.2 预算重分配：5,232 字符的去向（"裁员表"）

| v1 小节 | 约字符 | v2 去向 | 说明 |
|---|---|---|---|
| 身份 | 500 | P1 identity（压到 400） | 保留三条边界 |
| 配比（判断力 3:5:2） | 200 | `creatorNotes` + `mindset.judgement` | 决策依据给人看；数值进字段供 L0 断言 |

| **合计** | **≈5,232** | **P1 1,500 + P3 500 + P4 450 + P5 250 + P2 300** | **≈3,000（−43%）** |

> 一句话：**搬走的是"解释"，留下的是"事实"，移走的是"规则"，交给的是"机制"。** 这也是为什么这次升级不会再犯"加规则=变厚=收益为零"的老毛病（`adjustments L19`）。

## 7. 活人感的八个机制（本模块的核心价值）

### 7.1 见闻库（lorebook 等价）：解决"0 条个人经历"

**问题**：真人语料里经验分享占 **27.9%**（第二大类），我们 5 条里 **0 条**。而且模型没有"生活"，只能要么不说、要么编（红线禁止编事实）。

**方案**：维护一个**可检索的私人见闻库**，每条是一个"可以拿来用的具体经历"，带触发词：

```markdown
<!-- <家目录>/persona/lore/wuchang-ranked.md -->
---
id: wuchang-ranked
keys: [无畏契约, 瓦罗兰特, 上分, 掉段, 残局]
scope: game
tone: 自嘲
facts: ["常年在白银边缘", "队友太强我就送", "打排位前先吃碗饭"]
cooldown: 3          # 至少隔 3 轮才能再用
---
我打无畏契约，但一直在白银边缘反复横跳。上分靠队友，掉段靠自己。
最常发生的事：开局说好稳一手，五分钟后就剩我一个人在残局里被围观。
```

**关键设计：索引常驻、正文按需读。** 原因很硬：**候选视频在编译期是未知的**——prompt 在拉起子进程时就定死了，而"今天刷到哪些视频"是子进程里第 3 步才发生的（`duty.md` 一轮要做的事 1）。所以不可能像酒馆那样"编译期按关键词召回"。

于是采用两层：

1. **索引**（P2，≤8 行，300 字符）进 prompt：让模型知道"我有哪些经历可用"；
2. **正文按需读**：章程加一行（约 45 字）：

   > ⭐ 写评论前，若 P2 索引里有跟这条视频对得上的条目，先 `read` 它的正文再用；别凭索引编细节。

**冷却与防重复**：`state.json` 记录每条 lore 的 `lastUsedRound`，索引排序时把"冷却中"的排后面并标注"（今天别再用）"。上限：同一天同一 lore 最多用 1 次——否则会出现"每条评论都在讲我白银段位"的新的整齐感。

**质量约束**：lore 条目只允许写**不会被当真的事实**（吃饭、掉段、烧 token、看片习惯），禁止写新闻、职业、地理位置细节、可被核实的第三方事实。这条写进 `lore.js` 的校验（第 3 条事实必须是"第一人称体验"句式），控制台保存时提示。

**为什么这条能提升活人感**：它把"你要有个人经历"这种形容词，变成**模型可以直接抄用的素材**——这是酒馆 lorebook 最大的用途，也是我们当前最大的空洞。

### 7.2 状态与连续性：解决"5 条整齐得可怕 / 不像同一个人"

**问题**：10-25 的五条评论"整齐得可怕"（同一套句式 5 次），本质是**每一轮都是同一个零状态的人**：没有今天、没有最近、没有被自己上一句话约束。

**方案**：`<家目录>/persona/state.json`，**由宿主派生，不由模型编**：

```jsonc
{
  "date": "2026-10-26",
  "mood": { "label": "有点困", "energy": 4, "patience": 3, "seed": "2026-10-26" },
  "recent": {
    "comments": [ { "t": "…", "text": "…", "form": "judge", "endType": "judge" } ],  // 最近 3 条
    "forms5": ["judge","judge","info","judge","info"],                                   // 最近 5 条形态
    "debt": { "question": 0, "reaction": 0, "emoji": 0, "experience": 5 }               // 欠账
  },
  "loreUsed": { "wuchang-ranked": "2026-10-25T14:02:11Z" },
  "canonUsed": { "ask-ai": "2026-10-25" },
  "lastPersona": { "id": "whale", "version": "2.0.0", "hash": "9f2c1a" }
}
```

派生规则（全部确定性，可单测）：

| 字段 | 来源 | 规则 |
|---|---|---|
| `mood` | 日期 seed 的**确定性轮盘** | 8 种状态（困/精神/烦/佛系/饿/上头/蔫/来劲）× 按 `YYYY-MM-DD` 取模，**同一天内不变**。只允许表达"我自己的状态"，禁止衍生外部事实（不写"今天加班""刚下飞机"） |
| `recent.comments` | `ledger.jsonl` 最近 3 条 `type:"comment"` | 直接取 `text`；同时用 `lib/style.js` 算 `endType/form` |
| `debt` | 最近 5 条 `form` 统计 | 缺哪种形态就欠哪种：疑问 <1、纯反应 <1、带表情 <1 ⇒ 记欠账 |
| `loreUsed` / `canonUsed` | 账本 + 状态 | 冷却记账 |

**跨轮一致性的边界**：单轮公开评论没有对话上下文，所以"人格一致性"不能按多轮对话测（度量调研 §8）。能测的只有：① 跨轮自我重复（Jaccard）；② 形态轮换；③ 今天的心情是否在**同一天的多轮**里保持一致（这恰好是"活人"的信号：早上困、晚上来劲）。**不做**跨天记忆（会让模型编"昨天我…"）。

### 7.3 形态欠账：把"规则"变成"数据"

**问题**：`persona L50` / `duty L76` 写着"每 5 条里至少 1 条疑问、1 条纯反应、1 条带表情"，但 `commentsPerRound=2`（现在配置是 5），一轮根本凑不齐，规则从未被执行（10-25：5 条里 0 疑问、0 纯反应、0 表情）。

**方案**：宿主每轮算**欠账**，写进 P3 一行。模型不需要数，只需要照做：

```
⚠️ 最近 5 条：4 条收在判断上、0 条疑问、0 条纯反应 → 这条优先**疑问**或**纯反应**。
```

若一轮有 2 条额度，欠账行会写"本轮两条：一条疑问、一条纯反应"。这是**唯一**能保证配比被执行的形式——因为它是数据，不是劝告。

**未知时的降级**：账本不足 5 条（新号第一天）⇒ 不给欠账，改给"多试不同形态"一行。避免第一天就被强行写成"全是疑问"。

### 7.4 最后一公里：Author's Note 的等价物

`P5` 三行 + 一句对照（对照在 P4），是**唯一被允许重复**的内容。它不引入新规则，只做三件事：

1. **落点**：末 6 个字别收在判断上（换成情绪/问题/梗）——对应唯一有 17× 证据的因子；
2. **自足**：第一句单独拿出来，没看过视频的人能读懂吗；
3. **红线短促重申**：不碰政治/地域/性别/饭圈、不冒充真人、不提后台身份。酒馆的做法是"红线在常驻说一次，末尾再说一次"——因为末尾位只改行为，而"别踩线"恰恰是行为。

**"不发"的权力不放在这里**，放在 P3（额度/欠账区）：`接不上就点赞，别凑数。` 理由：末尾 3 行是竞争性资源，用来写"可以选择不做"会稀释前三条硬提醒；而"这轮有额度、可以不发"本来就属于本轮上下文。

> **注（我们的限制）**：酒馆的 `@D` 可以把提醒以 **user 角色**注入，服从度高于 system。本项目整轮 prompt 是**单条 user 消息**（`index.js:680` 作为 argv 传入），无法中途切换 role——所以 P5 只能靠"放在最后 + 极短"来取得同等效果。这也是为什么 P5 必须严格 3 行：我们没有 role 这个额外杠杆。

### 7.5 质量门（见 §8）与"不发"的权力

八条机制必须配一条**降级路径**：质量门连续失败 ⇒ **这条不评，只点赞**，并记为 `skip·quality-gate`（`ledger` 已有 `skip` 类型，零 schema 变更）。

这条不是"兜底"，而是**活人感的来源之一**：真人发评论的前提是"有话要说"，不是"这轮必须发两条"。当前的"配额是上限不是任务"（`duty L83`）之所以一直被违反，是因为**模型没有可执行的替代动作**；给它一个"合规的不发"，比再加十条"宁可少发"更有效。

### 7.6 说话决策与沉默退避：先决定"说不说"，再决定"怎么说"

**来源**：MaiBot 把人格拆成"她是谁 / **何时参与、何时安静** / 说话习惯"三段（`behavior_style`），并且把频率调优排在提示词之前（`talk_value`、`talk_value_rules`、`no_action_backoff`）；Pallas-Bot 同理。**我们缺的正是第二段。**

**问题**：现在"该不该评"和"怎么写"挤在同一段提示词里，模型只能**边判边写**——写出来的第一个动作必然是"我先评价一下"，这就是判断式收尾的结构性成因（F3），也是 5 条同型的成因（F2）。

**落地**：

1. 卡内 `behaviorStyle`（3 行）：什么场景开口 / 什么场景闭嘴 / 兴趣优先于价值；
2. **章程评论纪律第一条改成硬前置**：先给一个词的结论（`发` / `不发`），再写正文；`不发` ⇒ 只点赞/跳过。决策与表达串行，而不是并行；
3. **沉默退避按轮换算**（不照抄 15 秒）：`state.skipStreak ≥ 3` ⇒ 本轮最多发 1 条，且只能从"纯反应/玩梗"桶里取——低能量形态；
4. **楼中楼单列**：跟进回复的配额与形态与主评论分开算（≤40 字、允许 `哈哈`/`我也是` 这种纯反应），并**明确优先于铺新评论**。这是唯一有真实上下文、有对象、能自然说"我"的地方 → 也是"个人经历"最该出现的位置；
5. `relations.md`（可选，≤20 行）：只记"先回复过我的人"，只服务楼中楼，**不叫昵称、不提'上次你说过'**（装熟是红线，不是风格）。

### 7.7 语料库与生命周期：活人感的主要来源是语料，不是记忆

**来源**：Pallas-Bot 的核心做法是"按账号×群学习**什么场合常说什么**"，作为群表达指导注入；MaiBot 的 `expression` 学习 + 入库双闸门 + `max_reg_num`/`do_replace` 的容量淘汰。

**问题**：我们的"形态欠账"只给了**形态名**（"该发疑问"），模型于是写出一条**书面疑问**。欠的是形态名，缺的是**句子长什么样**。

**落地**：

- `persona/expression-bank.json`：按形态分桶（纯反应 / 疑问 / 个人经历 / 玩梗 / 补细节 / 吐槽），每桶 20–40 条，**每条必须来自真实热评**（首批用 247 条语料，之后逐月从账本+评论区补），带 `source`；
- 抽取：欠账 → 选桶 → **按 `heat` 反比加权 + 冷却** → 3–5 条注入 P4（不超 5 条，否则模型照抄）；
- 三条护栏：① 只注入 `active`；② 草稿与库中任一 `active` **字符重合 >60% ⇒ 直接拒绝**（防抄热评——那是平台红线，也是"水军"特征）；③ 注入时附一句"这些是别人怎么说，不是你改写"；
- 生命周期字段：`status(candidate|active|retired)` / `heat` / `lastUsed` / `ttlDays`；`active` 上限 120，满了按"heat 最低 + 最旧"淘汰。**见闻库与梗库共用同一张冷却表**——把"常备几个词"变成"配额 + 冷却"，这是"越用越旧、每轮像同一个人"（F4）的解药；
- 纠错通道：每条见闻必须带 `sourceBv` + `sourceQuote`，没有来源不许 `active`；发现误读就**原地标 `retired` 并写一行原因**（`corrections.md`），不许删了重记同样的错。

### 7.8 时段与作息的机器化

**来源**：MaiBot 把"凌晨更安静"写成默认配置（`time="00:00-08:59"` → `value=0.8`），而不是提示词。

**落地**：`state.timeOfDay`（凌晨/早/午/晚/深夜）由宿主算；偏置直接作用于**长度与形态**：深夜上限压到 40 字、禁"经验分享"长形态、允许半句与省略号；白天恢复。这是"每轮温度一样"最便宜的解——同一个人在不同时段本来就不一样。

## 8. 质量门：三层，全在发布之前

### 8.1 分层（按"谁能判定"分，不按"什么时候"分）

| 层 | 位置 | 手段 | 失败动作 | 成本 |
|---|---|---|---|---|
| **L0 静态** | CI / 保存时 | 卡结构校验、预算校验、红线词表自洽、`creatorNotes` 未注入、**6 条格式判据**（见下） | 拒绝保存 / CI 红 | 0 |
| **L1 确定性** | `bili_reply` 之前，**MCP 工具** | 长度、红线词、后台身份、`judgeTail`、`endType`、自足起手、`原来 A 是 B`、AI 套话、与自己近 3 条重复 | `FAIL(reasons)` → 只改失败项重写 **1 次** → 仍 FAIL ⇒ 不评 | 每轮 +1 次工具调用 |
| **L2 语义** | 同 L1 之后（模型自评） | 自足性、再创作层数、形态是否同型 | 二元答案写进报告一行 | 0 额外调用 |
| **L3 审计** | 发布后 / 周报 | 分布指标、不评率、golden set 扩充 | 告警，不改历史 | 0（读账本） |

**为什么 L1 必须是工具而不是提示词**：提示词是软约束（`adjustments L19` 已证"文档加厚收益为零"），而 `bili_reply` 不可撤回。工具是**唯一能真拦**的手段（度量调研 §6.2 方案 C）。同时它**不占人设 3,000 预算**——规则在代码里。

**L0 的六条格式判据**（全部纯字符串可判，成本为零；来自 GitHub 样例的实测结论，其中第一条与第四条现在就能在人设卡上查出来）：

| 判据 | 检查方式 | 现状 |
|---|---|---|
| **红线三件套** | 每条 `redlines[]` 必须有非空 `why` 与 `instead`，且 `instead` 不以"不要/别/禁止"开头 | 现状 13 条红线**全部是否定句、0 条有正向替代** → 必须重写 |
| **禁止句占比** | 禁止式句子 / 总句 ≤25%（>35% 拒绝保存） | 现状红线 11/13 以"不"开头，密度过高 → "人物变薄" |
| **手段表存在** | `card.moves` ≥6 类可做的事 | 现状只有梗库与样本，没有"可做清单" |
| **词频上限** | 同一实词出现 ≤3 次 | 现状 `鱼` **18 次**、`大肥鱼` 6 次 → 重复即加权 |
| **矛盾格式** | 每条 `contradictions` 含 `vs/但/却/又…又` 之一，且可拆成两个 ≥3 字短语 | 现状"自恋但怕被打脸"勉强过；"围观型乐子人"这类是标签，要拆 |
| **示例不重复** | `samples.good` 中同一 3-gram/梗 ≤1 条；每条必须有 `source` | 现状两条都含 `69：` 梗 → 会被逐字复读 |



| ID | 判据 | 阈值 | 挡住的真实事故 |
|---|---|---|---|
| `len` | 去 `[表情]`/空白后字符数 | 10 ≤ n ≤ 100，**不设区间门** | 空评论 / 超平台上限 |
| `redline` | 卡 `redlines` 的 lexicon/regex + 开关对应的争议词表 | 命中即 BLOCK，**不重写** | 政治/地域/性别/引战/后台身份/冒充真人 |
| `judgeTail` | 末 8 字命中判断词表（`得很/死了/这个了/说死了/实在/靠谱/给得足/到位/说透/不错/挺香/省心/细`） | **0 命中** | `…欠得很`、`…一下就说死了`（3/5 条） |
| `endType` | 分类为 `emotion/question/meme/judge/info/none` | 近 5 条 `emotion+question+meme ≥ 3` | 全是"抓细节+判断" |
| `selfContain` | 首句不以"这条/这期/视频里/刚才/前面/「」台词"起手 | **0 命中** | `摩根那句…` |
| `originalIs` | `/^原来/` 且 `endType==info` | **0 命中** | `原来 A 是 B`（2/5 条） |
| `aiCue` | 套话词表 | **0 命中** | `综上`、`作为一个` |
| `dup` | 与最近 3 条 2-gram Jaccard | **≤ 0.45** | 整齐得可怕 |
| `emoji` | 近 5 条带表情条数 | **≥ 1** | 0/5（真人 41.7%） |
| `hedge` | 骑墙词表：`各有优劣 / 不能一概而论 / 取决于具体情况 / 视情况而定 / 因人而异` | **0 命中** | 既不下判断也不给情绪，读者无从回应 |
| `support` | 客服/助手腔：`理解你的感受 / 建议你 / 希望对你有帮助 / 有问题随时问` | **0 命中** | 一眼不是评论区的人 |
| `copyBank` | 与 `expression-bank` 任一 `active` 的字符 2-gram 重合 | **≤60%**，超了直接拒 | 抄热评＝水军特征，也是平台红线 |
| `punct` | 分号 = 0、破折号 = 0、感叹号不叠用、单条 `[表情]` ≤2 | 见阈值 | 书面腔与表情轰炸 |

**校准边界（必须写进工具文档）**：这套规则在 12 条样本上 **7/7 负样本全拦、5/5 正样本零误拦**，但**自有 5 条失败评论漏 2 条**（"知识陈述"型，词表天然抓不到）→ 所以 `judgeTail` 只是**高精度初筛**，`endType=info` 的灰区必须交 L2 判（"这句是判断还是叙述？"）。

### 8.3 阈值纪律与"不评率"护栏

- **所有阈值必须能追溯到一行证据**（真人基线分位数 / 本项目 A/B），追溯不到的标 `猜`，**先 shadow 采数**。
- **shadow 模式先行**：前 1–2 周只记录不拦（报告里写 `质量门（shadow）：将拦下 X 条，原因 …`），用真实输出校准后再开硬拦。
- **过热保护**：`不评率 = quality-gate 跳过 / 候选数`，周环比 > 50% ⇒ 判定阈值过严，必须放宽。质量门最大的风险不是漏放，是把评论全拦掉。
- **指标优先级**：硬约束 > 落点 > 自足 > 再创作 > 风格护栏 > 分布。**任何"为了分布好看"的改动都不许破坏落点与自足**。

### 8.4 单一事实来源的技术实现（避免 JS/Python 两套规则漂移）

规则会同时被三处使用：① 子进程的 MCP 工具（Python）、② 宿主控制台预览/周报审计（JS）、③ 测试。**两份实现必然漂移**，所以：

```
dsh-plugin/lib/style/rules.json     ← 唯一规则源（词表、正则、阈值）
        │                    │
   mcp_server.py        dsh-plugin/lib/style.js
   （读同一份 JSON）      （读同一份 JSON）
        │                    │
        └──── test/style.conformance.test.js ────┘
              对 golden set 跑两个实现，断言判定完全一致
```

- Python 侧新增 `bili_lint_comment(texts) → [{pass, reasons[], metrics}]`，`BILI_MCP_TOOLS` 加一项；
- 同时给 `mcp_server.py` 加 `--lint` CLI 模式，宿主控制台可以直接 `spawn python mcp_server.py --lint-json`（无需起 MCP 会话）；
- **一致性测试是这套设计的控制点**：两份实现任一处改动导致 golden set 判定不同 ⇒ CI 红。允许的偏差要显式写进白名单（例如 Python 侧多一个中文分词差异），不允许"悄悄不同"。

## 9. 控制台：人设工作室（Persona Studio）

现状：一个人设 textarea + "保存并生效"（`client.js:1457-1466`），没有字数、没有预览、没有校验、不显示"生效的是正文还是文件"。升级后是**一个独立 tab**，六个页签。

### 9.1 页签与能力

| 页签 | 能力 | 解决现状哪个问题 |
|---|---|---|
| **卡片** | 分块表单（身份/口吻/品味/心态/红线/问答/见闻索引/示例），每块带字符预算条；"保存"时 L0 校验；支持"从内置预设开始"、"另存为副本" | 无结构、无样例入口、无校验（C1–C4） |
| **预览** | 显示**编译后的真实文本**（等宽、带块标与字符数/总长/预算条/argv 余量），并给"本轮状态模拟器"（选一个日期/mood 看 P3 变化） | 无预览、无生效态（B1/C3） |
| **质量** | 对示例库 + 最近 20 条真实评论跑指标面板：句号率/表情率/疑问率/判断收尾命中/形态分布/自我重复，与真人基线并排（带基线来源）；L0 断言结果 | 无 lint、无基线（C5/D5） |
| **语料库** | 六个形态桶的样本列表（新增/编辑/启停）、来源标注、`heat`/`lastUsed`/TTL、"抽 5 条看看"预览；批量导入（从 247 条语料/账本历史） | 缺"真实语料"，只有手写示例（A3） |
| **见闻库** | 条目列表（id/keys/冷却/上次使用）、新建/编辑、命中测试（输入一个视频标题看会召回哪几条） | 无素材（A3） |
| **状态** | 今日 mood/欠账/最近 3 条/冷却表，只读 + "重置今天" | 无状态（A5） |
| **版本** | 快照列表、diff（块级）、回滚、A/B 分组（A/B 各挂一个版本，按 roundId 交替） | 无版本（A4）、不可回滚 |

### 9.2 API（挂在现有 `/api/bili-fenshen/*` 命名空间下）

### 9.3 试写沙盒（这个功能值得单列）

给一个视频标题 + 两句简介/字幕片段，让模型按当前人设写 **3 条**候选评论，返回 **lint 结果 + 落点分类**，一条都不发。它解决两个现实问题：

1. 改人设是"盲改"：现在改完只能等下一轮真实发布才知道效果；
2. A/B 需要样本：沙盒能在一分钟内产出 30 条候选，用 golden set 判据打分，**不消耗账号行为配额**。

> 注意：沙盒的输出**不能**当作"活人感达标"的证据（同模型自评自写有偏置），只能当"回归是否退化"的快速体感。真实验收仍看发布后的点赞/回复与不评率。

## 10. 可观测与归因（让"人设有效"可被证明）

没有这一层，后面所有优化都只能靠人肉读日志（`log-findings` 332 行就是这么来的）。

| 埋点 | 位置 | 内容 |
|---|---|---|
| 账本轮次事件 | `ledger.jsonl` 的 `round-start` / `round-end` | `persona:{id, version, hash, chars, blocks:[…], preset|file}` |
| 评论/动态事件 | 同上 | `personaVersion`（冗余但便宜，便于单条归因） |
| 报告头 | `out/<date>.md` 每轮首行 | `人设：whale@2.0.0（hash 9f2c1a，4,280 字符）` |

| 诊断项 | `lib/diagnose.js` | 新增 3 项：人设是否生效（来源/字符/预算）、卡是否通过 L0、见闻库是否有可用条目 |
| 周报 | `out/quality-audit-YYYY-MM.md` | 分布指标 + 不评率 + 按人设版本分组的点赞/回复中位数 |

**A/B 的最小口径**：两个版本按 `hash(roundId) % 2` 交替；每臂至少 **20 条评论**才看指标（当前配额 15/天 ⇒ 约 3 天）；比较项固定为：① 被点赞率（有 `received_likes` 证据的条数/总条数）② 被回复率 ③ 不评率 ④ 判断收尾命中率。**不做显著性检验**（n 太小），只做"方向 + 幅度"判断，并在报告里写明样本量。

**压审的方法学红线**（写进诊断与周报）：只有**正向证据**（`received_likes`/`received_replies` 里出现该 rpid）才能判"可见"；"没进热评前 30"**不能**推断为压审（`comment-reception` 的方法学结论）。否则以后每轮都会有人拿它当调风格的理由。

## 11. 迁移与兼容（不能打断正在跑的号）

### 11.1 兼容矩阵

| 现状 | 升级后行为 |
|---|---|
| `personaPrompt` 为空 | **首次启动播种**：`active.json = {mode:'preset', presetId:'whale'}` —— **开箱即用就是「蓝色大肥鱼 / 不吃鱼的豆腐」**（账号主人明确要求；仓库已有 v1.0 卡可直接迁移）。控制台同时提供 elaina / generic 一键切换 |
| `personaPrompt` 是文件路径（当前真实配置就是 whale 路径） | 读文件 → 若是 v2 卡（JSON）直接用；若是旧 markdown ⇒ **legacy 直通**：内容原样注入（行为不变），控制台标"旧格式"，提供迁移预览 |
| `personaPrompt` 是内联正文 | 同上，legacy 直通 |
| 想继续用旧格式 | 永久支持：`legacy.js` 把文本包成"人设（旧格式）"块，位置同现在；**只是没有状态/见闻/欠账/尾注** |
| 老版本 `config.json` | 只加 `personaId` 字段（空=legacy/file），其余不动；`FIELDS` 白名单加一行 |
| 正在跑的一轮 | 编译在 spawn 前完成；保存人设**不影响**已启动的子进程（快照已落盘） |

### 11.2 旧 markdown → v2 卡的迁移器

自动迁移只做"机械拆分 + 人工确认"，**不做语义改写**：

1. 按 `##` 切节；
2. 标题命中映射表（身份→identity、配比/参数→mindset、标点与表情/打字纪律→voice、语气样本→samples.good、别这样写→samples.bad、红线→redlines、被问到→canon、梗库→voice.bannedWords/particles、在这个号的偏好→taste、其余→creatorNotes）；
3. 控制台展示"迁移预览"（左旧右新，逐块标"已识别/未识别"）；
4. 未识别的段落**默认进 `creatorNotes`**（不进 prompt），避免把解释性文字继续烧 token；
5. 用户确认后才写 `card.json`，旧文件保留不动（可回滚）。

**配比/参数行怎么办**：v1 的"判断力 3 : 社区味 5 : 本体 2"与末行"参数 …"合并为 `mindset.traits[] + judgement`；L0 断言强制二者一致（顺手修掉现存矛盾：`persona L17` 写判断力 3、`L180` 写 5）。

**开放问题（需要拍板/需要实测）**：

1. **默认预设用哪张卡？** ✅ **已定：`whale`（蓝色大肥鱼 / 不吃鱼的豆腐）**，开箱即用就是鲸鱼娘。需要随代码一起落的三条合规说明：

   - ② 插件本体 MIT 与人设数据（CC BY-NC-SA）**授权分离**：人设卡作为独立数据文件分发，不改变其条款，也不因此把插件整体变成 NC；
   - ③ 卡内红线必须保留"民间不是官方、只能非商业、是梗不是人"三条——默认人设一旦被换成"能接广告"的版本，就是账号风险，不是风格问题。
2. **`bili_lint_comment` 该不该让模型看见全部 reasons？** 看见能改对，但也可能"猜门"（过拟合）。建议：只回**首条** reason + `retryable` 标记。

4. **A/B 是否要按"视频类型"分层**？游戏区与科技区的点赞基线差异大，混在一起可能掩盖效果。建议 P5 再定。
5. **是否要给"人设卡"做导入/导出**（类似酒馆 PNG 卡生态）？本期不做，但 schema 已预留 `source/license`。

| 注入 | 五块齐全且位置正确、人设 ≤3,000、整轮 prompt ≤20,000（目标 ~10,200）；P5 **不含任何具体收尾句**；快照测试覆盖 |
| 状态 | 同一天 mood 稳定、跨天变化；时段生效；欠账行每轮出现；lore/梗冷却生效 |
| 语料库 | 6 桶各 ≥20 条且全带 source；抽样 3–5 条；`copyBank` 重合拦截生效；active ≤120 且可淘汰 |
| 质量门 | golden set 9/9 负全拦、5/5 正无误拦；不评率 <50%；shadow 期 ≥1 周 |
| 归因 | 每轮账本含 `persona{id,version,hash}`；prompt 快照可查；周报能按版本分组 |
| 控制台 | 七页签可用；保存校验 400；版本可回滚；沙盒不发任何写请求 |
| 回归 | 现有 112 条测试全绿；新增 ≥30 条；`npm test` 含 mjs |

### 15.4 术语（补 `CONTEXT.md`）

- **人设卡（persona card）**：v2 结构化人设数据（`card.json`），人设模块的唯一事实来源。
- **见闻库（lore）**：可召回的第一人称经历条目；索引常驻、正文按需读取。
- **表达库（expression bank）**：按形态分桶的真实热评语料，按欠账抽样注入；**只给手感不给内容**。
- **红线三件套**：每条红线必须写 `rule + why + instead`（不许 + 为什么 + 那要写成什么）。
- **手段表（moves）**：允许的收法分类（纯情绪/夸张失态/反问/玩梗/emoji/零信息），轮换用；**不写固定句子**。
- **欠账（form debt）**：最近 N 条缺失的评论形态，由宿主算出并写进 prompt。
- **最后一公里块（last mile）**：prompt 末尾的 3 行约束，Author's Note 的等价物。
- **沉默退避（quiet backoff）**：连续跳过若干条后，本轮降为"最多 1 条 + 低能量形态"。
- **质量门（quality gate）**：发布前确定性 lint，FAIL 重写一次，仍 FAIL 则不评。
- **legacy 直通**：旧 `personaPrompt` 原文注入，行为与升级前一致，不享受新机制。
